# Baseline report — 2026-11-20

This is the first snapshot of the playground. It is a starting point, not a result: the experiments that test the current hypotheses are mostly still running or planned.

## Window and source

- Window: 14 days ending 2026-11-20.
- Source: OMP session store via `scripts/collect.py`; aggregates only.
- Sessions: 51.

`eval_file_reads` is deliberately absent: the event table stores no code text for eval calls, so the metric cannot be grounded there. The weekly reviewer must label traces.

## What we found

1. **Project identity is the biggest structural gap.** 70.6% of sessions run in `--private-tmp--`. A session without a project root has no stable context, no repo rules, and no place for its evidence to land. This is a harness/environment problem, not a model problem.
2. **Bash is the dominant failure surface.** 5,437 calls at 11.05% errors. The next review should split this into routing violations, real command failures, and environment errors. Without that split, the number cannot choose an intervention.
3. **Context shake is measurable but not dominant.** 17.69% of entries were shaken. The earlier 64% figure used a different measure and window; do not compare them.
4. **The two recurring errors from the author's reflection are now labeled incidents.** They are recorded as `INC-0001` (premature turn ending) and `INC-0002` (eval file reads on root-only paths). Both are model-side at the surface; `INC-0002` has a harness-side root cause.

## What changed

Sixteen deliberate interventions are mapped to claims in `mapping/omp-changes.toml`:

- 7 are hypotheses, each with an experiment and a falsifier;
- 9 are decisions, each with a `D-*` constraint;
- 0 are unmapped.

The mapping is not a claim that every intervention works. It is a claim that every intervention has a stated reason and a way to be wrong.
